# /product:refine

Refine an existing hosted product change through a graph-guided, question-driven interview.

Use the `refine-product` skill and the active host adapter. If no existing change is identifiable, ask the user to select one or create one through the host's normal workflow.

- Read the existing change and run its proportional integrity pass: compare intent with the whole model, widen through graph neighbours and impact polarity, and report candidates as affected, checked and unaffected, or uncertain. Rank product risks and agree the sitting's scope with the user.
- Ask one question at a time: quoted artifact text, the uncertainty, concrete options with consequences, a recommendation when the evidence supports one. Record every answer verbatim; park what the user cannot decide.
- Persist the report, queue, verbatim answers, parked questions and exclusions in the same hosted change's working memory; distil decisions into its change manifest and validate its overlay through the host adapter.
- Stop at the handover. Approval, apply and archive remain separate host actions; never edit accepted product truth directly.
