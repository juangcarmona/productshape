# apply-change: a project's own format

Where a project keeps plan artifacts in its own shape, author this role against the contract rather than adopting a tool.

The contract requires only that the artifact is **reviewable, committed on the branch, and carries four things**: a proposal (why and what), a design (how, and the trade-offs), tasks (the ordered work), and a test plan (what proves it, and which Definition of Done items it will satisfy).

Record in the configuration where these live and what they are called, so every stage finds them the same way.
